# v6 提示词的内部冲突

提示词按「逐字不变」的要求原样落进 `prompts_v6.py`，**一个字没改**。
下面三处是落地时发现的自相矛盾，都能用脚本复核，不是观感。
改不改由你定 —— 但在跑之前知道它们存在，比拿到坏结果再回头找原因省事。

复核脚本：

```bash
python3 - <<'PY'
import re, json, prompts_v6 as p
print([len(t) for t in re.findall(r'"title":\s*"([^"]+)"', p.SYSTEM_V6)])
m = re.search(r'━━━ 正确示范 ━━━\n(\{.*?\n\})\n\n━━━', p.FEWSHOT_V6, re.S)
print([sorted(c.keys()) for c in json.loads(m.group(1))["chapters"]])
PY
```

---

## 冲突 1（最要紧）—— FEWSHOT 的正确示范没有 `sections` 层

SYSTEM 规定的 schema 是三级嵌套：

```
chapters[] → sections[] → paragraphs[]
```

但 FEWSHOT「正确示范」里，`chapters` 的四个元素实际字段是：

```
no='5.15'  字段=['end', 'no', 'paragraphs', 'start', 'title']
no='5.16'  字段=['end', 'no', 'paragraphs', 'start', 'title']
no='5.17'  字段=['end', 'no', 'paragraphs', 'start', 'title']
no='5.18'  字段=['end', 'no', 'paragraphs', 'start', 'title']
```

`paragraphs` 直接挂在 `chapters` 元素下，**`sections` 整层不存在**。

而且编号是 `5.15`~`5.18` —— 这是「章5 的第 15~18 节」的写法，却放进了 `chapters` 数组。
示范实际展示的是**节**，标签写的是**章**。

这和 SYSTEM 里「全篇通常 4-10 章，超过 12 章说明你把『节』当成『章』了」直接打架：
唯一的正面例子本身就在把节当章。模型在「抽象规则」和「具体示范」冲突时，
通常跟示范走 —— 大概率输出一堆 `no` 形如 `x.y`、没有 sections 层的扁平结构。

**已做的处置**：`v3.parse_v3` 加了容错，遇到「章下直接挂 paragraphs」时合成一个
覆盖全章的节并打 `synthesized: true` 标记。两种形状都能解析，不会再出现整篇 0 节 0 段。
但这只是止损 —— **评测时若 `synthesized` 为真的节占多数，节级 F1 就没有意义**，
因为那一层是脚本补的，不是模型切的。跑完先看这个标记。

**若要修**：把示范的 `no` 改成 `3`、`4` 这样的整数，补上 `sections` 层，
补上 `trigger`/`evidence`/`confidence`（见冲突 2）。或者反过来，
如果你真想要的就是扁平两级，那该改的是 SYSTEM 的 schema 和「章 4-10 个」的数量判据。

## 冲突 2 —— FEWSHOT 缺了 SYSTEM 要求的三个「章」字段

SYSTEM 的字段说明写明：

- `trigger`：仅「章」需要，取值 A/B/C/D
- `evidence`：引用触发该章边界的那一行片段（20 字内）
- `confidence`：0-1，低于 0.7 的同时写进 `uncertain`

FEWSHOT 的四个 chapters 元素**一个都没带**，顶层也没有 `uncertain` 数组。

后果：`evidence` 是这套提示词里唯一能让人事后核对「这刀为什么切在这」的字段，
`confidence` + `uncertain` 是唯一的自评信号。示范里全缺，模型很可能照缺不误，
这两个可审计性设计就白写了。

## 冲突 3 —— SYSTEM 自己的 schema 示例违反 SYSTEM 自己的 title 规则

SYSTEM 规定 title「25~50 字，书面语」。但它紧挨着的 JSON 格式示例里：

| title | 字数 |
| --- | ---: |
| 引言:讲道框架与说明 | 10 |
| 讲道分两部分 | 6 |
| 分两个部分来讲 | 7 |
| 第一部分:1-5节约伯的现实背景 | 16 |
| 第二部分:6-8节约伯的属灵背景 | 16 |

**5 条全部低于下限**，最短的只有 6 字。

对照之下 FEWSHOT 是达标的：16 条 title，31~43 字，中位 39，**16/16 落在区间内**。

所以同一份提示词里，格式示例演示的是「短标签」，正例演示的是「长检索句」，
两种风格差 3~6 倍。title 的用途是向量检索，长短直接决定召回质量，
这个不一致值得优先修 —— 把 SYSTEM 的 JSON 示例 title 换成 25~50 字的写法即可。

---

## 一句话

冲突 1 影响结构层级能不能用，冲突 2 影响结果能不能审计，冲突 3 影响检索质量。
三处都在「示例」和「规则」之间，而模型更容易跟示例。
