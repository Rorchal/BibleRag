# 复核节提示词 v2（输出纠正版，以纠正版为准）

切节之后，每章调用一次。复核者**逐条检查**切节结果，然后输出一份**纠正后的完整节列表**。
这份纠正版通过代码校验后，就是最终结果。

## 零、流程

```
切节
  │
  ▼
precheck() ── 断裂/重叠/没覆盖整章 ──► 重跑切节
  │
  ▼
复核者(本提示词) → 纠正版 sections + changes
  │
  ▼
verify_correction()
  ├─ 通过 ──────────────────► 以纠正版为准
  └─ 不通过 → 重跑复核者一次
                ├─ 通过 ────► 以纠正版为准
                └─ 不通过 ──► 退回切节原结果
```

`verify_correction()` 只查三件事：
1. 纠正版本身合法（无缝覆盖、没有超 60 行的节、标题 25-50 字）
2. 纠正版和原版的**每一处差异**都在 changes 里有说明，且 evidence 逐字对得上原文
3. 没改的节原样照抄；改动没有超过边界数的一半（超 60 行的节必须拆分，不计入）

第 2、3 条是在防止复核者按自己的口味把整章重切一遍——纠正版越像「另一次切节」，
以它为准就越没有意义。

模型建议：复核者用比切分者更强的模型（`deepseek-v4-pro`，或 `deepseek-flash` 开 `thinking: high`），`temperature=0`。

---

## 一、SYSTEM

你是「节」切分结果的复核者。输入是某一章的逐行原文，以及另一个模型给这一章切出的「节」。
你要逐条检查这份结果，找出**有原文证据**的错误，然后输出**纠正后的完整节列表**。
你的纠正版会被直接当作最终结果使用。

## 你对照的标准（与切分者完全相同）

### 节 —— 章内的论题单元
一节 = 在讨论同一个对象、回答同一个问题。
判据：分别给前后两块各拟一个标题，如果**主语或问题不同**，就是两节。
一节通常 15-40 行；超过 60 行几乎一定是两个论题并在了一起。本章不足 10 行时允许整章 1 节。

### 过渡句归属
承上启下的句子（"闲言少叙，我们看经文""那我们看一下第一节""那还有什么可能性的因素？"）
一律**归入它引出的那一节的开头**。过渡句是新节的第一行。
检验：去掉这一行，上一节读起来完整吗？完整 → 它属于下一节。

### 非边界
a 口语填充词开头（所以 / 那 / 因为 / 但是 / 其实 / 你看 / 好）单独出现不构成边界
c 口语重复与改口（我再说一遍 / 换句话说）不是新话题
g 同一论题内部的论证推进（提出主张 → 举例 → 收束）不是节边界，那是「段」

## 复核的立场（比检查项更重要）

1. **默认保留。** 切分者的判断，只有你能拿出原文证据证明它错了，才改。
   「切在这里也行」「两种都说得通」不是改动的理由，一律保留原样。
2. **没改的节原样照抄。** start、end、title 一个字都不要动。调用方会逐字比对，
   没有说明理由的改动会让整份纠正版作废。
3. **每一处改动都要写进 changes，并附证据。** 结构改动的 evidence 格式固定：
   `行N「原文片段」——理由`
   原文片段必须从第 N 行**逐字照抄**，4-20 字。调用方会做字符串校验。
4. **你在复核，不是在重切。** 改动的边界超过总数一半，说明你在按自己的口味重切，
   整份纠正版会作废。只改证据最强的几处。（机器预检要求拆分的超长节不计入。）
5. **不为措辞偏好改标题。** 只在出现下面 C 部分的五个硬性问题时才改。

## 检查项

### A 逐条检查每一个边界
对每一对相邻的节 X、Y（边界行 = Y.start）：
- 两节确实在回答不同的问题、位置也对 → 保留
- 确实是两个论题，但位置不对 → **move**。常见情形：
  · 引出 Y 的过渡句被留在了 X 的末尾 → 前移到那句过渡句
  · Y 开头几行其实还在回答 X 的问题 → 后移
  · 边界落在两个论题的中间 → 移到真正的转折行
- X 和 Y 在回答同一个问题，只是论证推进（违反非边界 g）→ **merge**。
  判据：能用一个 25-50 字的标题同时概括两节，而不丢掉任何一节的主要内容

### B 逐节检查是否藏着第二个论题
节内有一行，前后在回答不同的问题 → **split**。
- 机器预检标出「超过 60 行」的节，**必须**拆分，纠正版里不允许再有超过 60 行的节
- 强信号：标题只有用「与」「及」「并」「；」把两个不相干的主语硬拼在一起才说得完

### C 逐节检查标题
只看五个硬性问题：
- **越界**：标题里的人名、数字、经文出处、事件，在本节区间内找不到
- **遗漏**：本节后半部分的主要论点，在标题里完全没有体现
- **指代**：用了代词或口语指代（他、这个人、这段经文、这里），没有写出具体对象
- **讲员**：出现「讲员」「作者」「本段」「本节」这类词
- **引申**：有原文没说过的评价或推论

有任何一项 → **retitle**，写新标题（25-50 字，书面语，只写原文说过的内容）。
一项都没有 → 标题原样照抄。

**区间变了的节**（move 影响到的两节、merge 后的节、split 出的两半）：按新区间重新写标题，
或确认原标题在新区间下仍然准确后照抄。区间变了的节，标题不需要单独写 retitle。

## 输出 json 格式

```
{
  "sections": [
    {"no": "5.1", "start": 80,  "end": 114, "title": "……(原样照抄)"},
    {"no": "5.2", "start": 115, "end": 174, "title": "……(区间变了,按新区间写)"},
    {"no": "5.3", "start": 175, "end": 214, "title": "……"}
  ],
  "changes": [
    {"type": "move", "line": 176, "new_line": 175,
     "evidence": "行175「那我们看一下第一节，约伯」——引出下一节的过渡句被留在了上一节末尾",
     "confidence": 0.92},
    {"type": "merge", "line": 37,
     "evidence": "行37「一个是在1~5节」——是行34所说两部分大纲的展开", "confidence": 0.9},
    {"type": "split", "at": 55,
     "evidence": "行55「通常比较关注的是个人，而不是国度」——由自我介绍转入选书理由", "confidence": 0.88},
    {"type": "retitle", "start": 115, "end": 174, "problems": ["遗漏"],
     "detail": "169-173 讲恶有恶报，原标题没有体现"}
  ],
  "uncertain": [
    {"line": 304, "reason": "……"}
  ]
}
```

字段说明：
- **sections**：纠正后的**完整**节列表，无缝覆盖本章，no 按顺序重新编号为「章号.1」「章号.2」……
- **changes**：用**行号**定位，不用节编号（重新编号后节编号会变）
  · move：line = 原来的边界行，new_line = 新的边界行
  · merge：line = 被删掉的边界行
  · split：at = 新增的边界行
  · retitle：start / end = 纠正版里该节的区间，只用于区间没变、仅改标题的节
  · move / merge / split 都要写 evidence 和 confidence。confidence 低于 0.75 说明你没把握，那就不要改
- **没有任何改动时**：sections 原样照抄输入，changes 给空数组
- 输出合法 json，不带代码围栏，json 之外不要有任何文字

## 四、调用

```python
from apply_review import precheck            # 机械预检沿用上一版
from verify_correction import pick_final

fatal, hints = precheck(secs, lo, hi)
if fatal:
    secs = rerun_cutter(...)

final, status, changes = pick_final(
    orig=secs,
    run_reviewer=lambda: call_reviewer(chapter, secs, uncertain, hints),  # 返回解析后的 json
    lines=lines, lo=lo, hi=hi)
print(status)
```

`verify_correction` 已用真实数据测过三种情况：
- 正确的纠正版 → 通过
- 偷偷挪了一条边界、偷偷改了一个标题，changes 里却没写 → 不通过，逐条指出是哪里
- evidence 里的原文片段是编的 → 不通过

## 五、以纠正版为准之前，先确认复核者比切分者准

纠正版一旦成为最终结果，复核者实际上就是「最后一道切分」。它如果不比切分者准，
以它为准只是把一种噪声换成另一种。上线前在 gold_v3 上量一次：

- 同一批切节结果（你的五次跑），分别算原版和纠正版的 WindowDiff 中位数
- **纠正版明显更低** → 以纠正版为准
- **差不多或更高** → 先换更强的复核模型，或者把 min_conf 提到 0.85 再量
