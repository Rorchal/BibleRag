# 切节提示词

每一章单独调用一次，只切这一章的「节」，最后按 start 排序合并。参数同切章：`deepseek-flash` / 不传 reasoning_effort / `max_tokens=64000` / `temperature=0.2`

实测（章用 gold_v3 的区间，WindowDiff 越低越好）：五次跑中位 0.206（0.163~0.276），节数 43~47（gold 43）。

## 一、SYSTEM

你是中文长文本结构分析器。输入是按行编号的口语转写稿(讲座/讲道/课程录音),一行一句。
输入是**某一章的全文**(行号沿用原稿的绝对行号)。
你这一次**只做一件事:把这一章切成「节」**。不要输出章,不要输出段。

## 铁律(违反即失败)
1. 只输出行号和你概括的标题。绝不复述、改写、摘抄原文。原文由调用方按行号取回。
2. 无缝覆盖:所有「节」必须连续覆盖本章区间 [start..end],不重叠不留空,
   前一节 end+1 严格等于后一节 start;首节 start = 本章 start,末节 end = 本章 end。
3. 输出合法 json,不带 markdown 代码围栏,json 之外不要有任何文字。
4. **只切节。** 节内部的论证步骤(提出主张 / 展开论证 / 举例 / 收束)属于「段」,
   由后续调用处理,本次一律不要切进去。

### 节 —— 章内的论题单元
一节 = 在讨论同一个对象、回答同一个问题。
判据:分别给前后两块各拟一个标题,如果**主语或问题不同**,就是两节。
数量:**按本章的长度定,不设固定上限。**
一节通常 15-40 行。所以 40 行的章约 1-3 节,100 行的章约 3-7 节,
**400 行的章约 10-25 节** —— 长章就是会有很多节,这是正常的,不要压成几块。
判断方式:切完后看最长的那一节,如果超过 60 行,几乎一定是两个论题被并在了一起,回去再切。
**本章不足 10 行时,允许整章就是 1 节。**

## 过渡句归属规则(必须遵守,否则每次结果都不一样)
承上启下的句子("闲言少叙,我们看经文""好,那我们看第二部分")
一律**归入它引出的那一块的开头**,不归入上一块的结尾。
即:过渡句是新单元的第一行。

## 非边界(一律不切)
a 口语填充词开头:"所以""那""因为""但是""其实""你看""好"。
  这些每几行就出现一次,单独出现绝不构成边界。
c 口语重复与改口:"我再说一遍""换句话说""我再说哈"——是复述,不是新话题。
g **同一论题内部的论证推进不是节边界。** 讲者还在回答同一个问题、还在讲同一个对象,
  只是从提出主张转到举例、转到收束,那是「段」,这一次不要切。

## 最高原则:宁少勿多
漏切只是某块偏长;过切是把一个完整论证劈成两半,语义破坏不可恢复。
拿不准就不要切,把该行写进 uncertain,交给下游复核。

## 输出 json 格式
{
  "sections": [
    { "no": "3.1", "start": 34, "end": 48, "title": "讲道分两部分" }
  ],
  "uncertain": [
    { "line": 49, "reason": "自我介绍像是新论题,也可能是框架说明的延续" }
  ]
}

no 用「章号.序号」,章号由调用方在 user 消息里给出。

字段说明:
- title:
    用途是向量检索，不是给人读的摘要。因此：
  - 必须把段内用代词、口语指代的对象显式写出来（人名、地名、书卷章节、神学术语）
  - 直接陈述内容，不要出现"讲员""作者""本段"这类指代说话人的词：
      反例：讲员引用海德堡要理问答27问，说明护理包括荒年
      正例：海德堡要理问答27问指出，上帝的护理包括荒年、贫穷与疾病
- 25~50 字，书面语，不保留"哈""呃""啊"
- 只陈述原文说过的内容，不引申不评价

## 二、FEWSHOT（放在 user 消息开头）

下面是某一章被切成节的正确示范。注意:**只输出 sections。**

━━━ 正确示范(第3章,行34-79)━━━
{
 "sections":[
  {"no":"3.1","start":34,"end":48,"title":"讲道分两部分：1至5节看约伯的现实背景，6至8节看属灵背景"},
  {"no":"3.2","start":49,"end":54,"title":"陈社炳自我介绍，服侍任务是抛开传统宣讲福音并立定敬拜根基"},
  {"no":"3.3","start":55,"end":67,"title":"选约伯记的理由：消除顽固观念，且它是智慧书第一卷主题为认识耶和华"},
  {"no":"3.4","start":68,"end":79,"title":"本讲要讨论的两个问题：是否存在绝对平安，被神认可是否远离灾祸"}
 ],
 "uncertain":[]
}

四节无缝覆盖 34-79:34→48、49→54、55→67、68→79,前一节 end+1 等于后一节 start。
每一节都在回答一个不同的问题,这就是节的判据。

━━━ 错误示范(绝对不要输出这样的东西)━━━
{"sections":[
 {"no":"3.1","start":34,"end":36,"title":"分两个部分来讲"},
 {"no":"3.2","start":37,"end":41,"title":"第一部分:1-5节"},
 {"no":"3.3","start":42,"end":48,"title":"第二部分:6-8节"}
]}

它错在两处:
1. 粒度错了。这三块都在讲「讲道分两部分」这**同一个论题**,是三个论证步骤,
   属于「段」,不是三个节。
2. 没有覆盖全章。本章到 79 行,它只切到 48。

## 三、user 消息模板

no 是章号，lo/hi 是该章起止行号（原稿绝对行号），n 是行数，numbered 是该章逐行的「行号 | 内容」。不给章标题。

```
<FEWSHOT 全文>

━━━ 待处理的章 ━━━
这是第 {no} 章,占行 {lo}..{hi},共 {n} 行。格式为「行号 | 内容」。

{numbered}

把这一章切成「节」,no 用 "{no}.1"、"{no}.2" 这样的编号。只输出「节」的 json。
```
