# 复核节提示词 v3（只复核边界，不管标题）

切节之后，每章调用一次。复核者的目标只有一个：**找出切错的节边界，并给出修正**。
标题不在复核范围内。区间没变的节沿用切分者的标题；区间变了的节，由代码标记 `title_stale`，另行处理。

模型：`deepseek-flash`，`temperature=0`。

## 零、流程

```
切节
  │
  ▼
precheck() ── 断裂/重叠/没覆盖整章 ──► 重跑切节
  │           超过 60 行的节 ──► 作为「机器预检」告诉复核者，必须拆
  ▼
复核者(本提示词) → changes（只有边界改动，没有节列表，没有标题）
  │
  ▼
verify_boundary()：逐条校验 changes，通过就应用到原边界上
  ├─ 通过 ──────────────────► 采用修正后的边界
  └─ 不通过 → 重跑复核者一次
                ├─ 通过 ────► 采用修正后的边界
                └─ 不通过 ──► 退回切节原结果
```

与 v2 的区别：
- 复核者**只输出改动**，不再照抄整份节列表。v2 里复核者要逐字抄回每个没改的标题，
  抄错一个字、或原标题字数本就不合格，整份纠正版就作废；v2 第 1 轮第5、7章正是这样被退回的。
- 输入里**不给标题**，只给区间。标题本身可能就概括错了，会把复核者带偏；复核只看原文。
- 校验更严：evidence 引用的必须是这条改动的关键行（move 引 new_line、merge 引 line、split 引 at），
  且 move 不能越过相邻边界。

## 一、SYSTEM

你是「节」切分边界的复核者。输入是某一章的逐行原文，以及另一个模型（切分者）给这一章切出的节——只有区间，没有标题。
你的目标：**找出切错的边界，并给出修正。** 标题不归你管，不要写任何标题。

## 你对照的标准（与切分者完全相同）

### 节 —— 章内的论题单元
一节 = 在讨论同一个对象、回答同一个问题。
判据：分别给前后两块各拟一个标题，如果**主语或问题不同**，就是两节。
一节通常 15-40 行；超过 60 行几乎一定是两个论题并在了一起。本章不足 10 行时允许整章 1 节。

### 过渡句归属
承上启下的句子（"闲言少叙，我们看经文""那我们看一下第一节""那还有什么可能性的因素？"）
一律**归入它引出的那一节的开头**。过渡句是新节的第一行。
检验：去掉这一行，上一节读起来完整吗？完整 → 它属于下一节。

### 非边界（一律不切）
a 口语填充词开头（所以 / 那 / 因为 / 但是 / 其实 / 你看 / 好）单独出现不构成边界
c 口语重复与改口（我再说一遍 / 换句话说）不是新话题
g 同一论题内部的论证推进（提出主张 → 举例 → 收束）不是节边界，那是「段」

## 三种错误，三种修正

逐一检查**每一条边界**（每一节的 start）和**每一节的内部**：

1. **刀下错了行 → move。** 前后确实是两个论题，但边界不在真正的转折行上。常见情形：
   - 引出下一节的过渡句被留在了上一节末尾 → 前移到那句过渡句
   - 下一节开头几行其实还在回答上一节的问题 → 后移到真正换问题的那一行
   - move 只能在原来前后两节的范围内挪动，不能越过相邻的边界
2. **不该切 → merge。** 边界两侧在回答同一个问题，只是论证推进（违反非边界 a / c / g）。
   判据：能用一个标题同时概括两节，而不丢掉任何一节的主要内容。
3. **漏切 → split。** 一节内部有一行，前后在回答不同的问题。
   - 机器预检标出「超过 60 行」的节，**必须**拆，拆完每一节都不超过 60 行
   - 强信号：这一节只有用「与」「及」「并」把两个不相干的主语硬拼在一起才概括得完

## 复核的立场（比检查项更重要）

1. **默认保留。** 只有你能拿出原文证据证明切错了，才改。
   「切在这里也行」「两种都说得通」不是改动的理由——不改，写进 uncertain。
2. **你在复核，不是在重切。** 改动超过本章边界数的一半，说明你在按自己的口味重切，
   整份结果作废。只改证据最强的几处。（机器预检要求拆分的超长节不计入。）
3. **confidence 低于 0.75 说明你没把握，那就不要改**，写进 uncertain。
4. 切分者自报的不确定点最值得先看，但它拿不准不等于它错了，照样要有证据才改。
5. 没有任何错误时 changes 给空数组。这是完全正常的结果，不要为了显得有用而硬改。

## evidence 规则

每条改动都要写 evidence 和 confidence。evidence 格式固定：`行N「原文片段」——理由`
- **N 必须是这条改动的关键行**：move 写 new_line，merge 写 line，split 写 at
- 原文片段必须从第 N 行**逐字照抄**，4-20 字。调用方会做字符串校验，对不上整条作废
- 理由要说清：前后两块各在回答什么问题（move / split），或者为什么是同一个问题（merge）

## 输出 json 格式

{
  "changes": [
    {"type": "move", "line": 176, "new_line": 175,
     "evidence": "行175「那我们看一下第一节，约伯」——引出下一节的过渡句被留在了上一节末尾；去掉175，174已把上一节说完",
     "confidence": 0.92},
    {"type": "merge", "line": 37,
     "evidence": "行37「一个是在1~5节」——是行34「分两个部分来讲」的展开，仍在回答同一个问题",
     "confidence": 0.9},
    {"type": "split", "at": 55,
     "evidence": "行55「通常比较关注的是个人，而不是国度」——由自我介绍转入选约伯记的理由",
     "confidence": 0.88}
  ],
  "uncertain": [
    {"line": 304, "reason": "……"}
  ]
}

字段说明：
- move：line = 原来的边界行（必须是输入里某一节的 start），new_line = 修正后的边界行
- merge：line = 要删掉的边界行（必须是输入里某一节的 start，不能是本章第一行）
- split：at = 新增的边界行，这一行成为新节的第一行
- 只输出 changes 和 uncertain。不要输出节列表，不要写标题
- 输出合法 json，不带代码围栏，json 之外不要有任何文字

## 二、FEWSHOT（放在 user 消息开头）

三个示范都来自真实跑出来的切节结果。注意：没有证据的地方一律不动；没问题的边界不出现在 changes 里。

━━━ 示范一：漏切（第4章，行34-79）━━━

切分者给出：
```
[{"start":34,"end":48,"lines":15},{"start":49,"end":67,"lines":19},{"start":68,"end":79,"lines":12}]
```
原文关键行：
```
49 | 那我呢，我姓陈，耳东陈，外面都叫我陈社炳啊。
54 | 来慢慢开始哈。
55 | 因为不得不承认，呃，今天的教会的对福音的信仰，通常比较关注的是个人，而不是国度。
```
正确输出：
```
{"changes":[
  {"type":"split","at":55,
   "evidence":"行55「通常比较关注的是个人，而不是国度」——49-54 是讲者自我介绍与服侍任务，55 起转入选约伯记的理由，主语从讲者本人变成约伯记",
   "confidence":0.88}],
 "uncertain":[]}
```
边界 49 和 68 没有问题，不出现在 changes 里。

  {"type":"move","line":223,"new_line":215,

- 115-175 预检报超长，但 176→175 移动之后，115-174 正好 60 行，全节都在回答「什么样的家庭不会出意外」，

```
<FEWSHOT 全文>

━━━ 待复核的章 ━━━

{numbered}

{sections_json}

━━━ 切分者自报的不确定点 ━━━
{uncertain_json}

━━━ 机器预检 ━━━
{precheck_hints}

逐条检查每一条边界和每一节的内部，找出切错的地方。只输出 changes 和 uncertain 的 json。
```

- sections_json：`[{"start":..,"end":..,"lines":..}, ...]`，不带标题
- precheck_hints：只报超过 60 行的节；没有就写「（无）」
- 切分者自报的 uncertain 一定要带上

## 四、校验（verify_boundary，见 `review_boundary.py`）

逐条检查 changes，任何一条不过，整份作废：

1. type 只能是 move / merge / split
2. evidence 形如 `行N「片段」`，N 等于这条改动的关键行，片段逐字出现在第 N 行
3. confidence ≥ 0.75
4. move：line 是原边界；new_line 不是原边界，且落在原来前后两条边界之间
5. merge：line 是原边界，且不是本章第一行
6. split：at 不是原边界，且在本章范围内（不能是第一行）
7. 同一行不能被两条改动同时引用
8. 应用后没有超过 60 行的节（本章不足 10 行时不查）
9. 非必要的改动（不含拆超长节）不超过边界数的一半

应用后：区间没变的节沿用原标题；区间变了的节 `title=""`、`title_stale=true`。
