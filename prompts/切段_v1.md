# 切段提示词 v1（节已知，只切段）

- **调用方式**：每一节单独调用一次，只切这一节的「段」，最后按 start 排序合并。
  不足 6 行的节不必调用模型，直接整节作为 1 段，只需补写标题。
- **参数**：`deepseek-flash` / `temperature=0.2` / `max_tokens=64000` / JSON 模式 `response_format={"type":"json_object"}`。
  `effort` 建议 none 和 low 各跑 5 次比较：「读完整段再写标题」这条要求，推理多一点通常更守得住。
- **拼法**：SYSTEM 放 system 消息；FEWSHOT 拼进 user 消息开头，后接「待处理的节」（模板见第三部分）。
  SYSTEM + FEWSHOT 每次调用都相同，可以吃到前缀缓存。
- **校验**：输出先过 `verify_paragraphs.py`，有致命问题就重跑一次，再不过就报人工。
- **防泄漏**：规则里的例句和示范全部取自**伯1:9-22**（行 158-177、195-222），不含伯1:1-8 的任何原句。
  可以继续用伯1:1-8 评测，**不要用伯1:9-22 评测**。
  （v8 的示范是伯1:1-8 行 467-556，过渡句例子 175/215/850/948 也来自伯1:1-8，
  而评测用的正是这一篇，所以 v8 的 0.222 有泄漏。）

和 v8 相比改了什么：
1. 只切段。章、节的定义和规则全部删掉，输入就是一节。
2. 输出先写 `cuts`（全部切点），再逐段写标题。切点定完，才开始写标题。
3. 每段在标题之前先写 `ending`：这一段最后两三行落在什么内容上。它只用来保证模型读到了段尾，标题不必包含它。
4. 标题 20-110 字，长度随段长；要求写成通顺的完整句子，并列出「不能脱离原文」具体指什么。
5. 非边界 a 改写：连接词既不是切的理由，也不是不切的理由（节级的实测里，把它写成「不切」导致了大量漏切）。
6. 段长按 gold 的实际分布改为「通常 5-12 行，中位约 8 行」（gold 113 段，中位 8 行，最长 16 行只有 1 段超过）。

## 一、SYSTEM

你是中文长文本结构分析器。输入是按行编号的口语转写稿(讲座/讲道/课程录音),一行一句。
输入是**某一节的全文**(行号沿用原稿的绝对行号),以及这一节的标题。
你这一次**只做一件事:把这一节切成「段」,并给每一段写标题**。不要改动节的范围。

## 铁律(违反即失败)
1. 只输出行号、ending 和标题。绝不复述、摘抄原文。原文由调用方按行号取回。
2. 无缝覆盖:本节的所有「段」必须连续覆盖本节区间 [start..end],不重叠不留空,
   前一段 end+1 严格等于后一段 start;首段 start = 本节 start,末段 end = 本节 end。
3. 输出合法 json,不带 markdown 代码围栏,json 之外不要有任何文字。
4. 顺序固定:**先定全部切点(cuts),再逐段写 ending 和 title。** 切点没定完之前,不写任何标题。

## 段 —— 节内的论证步骤
一段 = 一个完整的论证动作。常见的动作有:
- 提出一个主张,或抛出一个问题
- 解释、展开这个主张(包括自问自答、解释一个词)
- 举一个完整的例子、讲一段经历、打一个展开了几行的比方
- 引用或诵读一段经文
- 收束:回到主张、下结论、引出对听众的应用

**判据**:给前后两块各写一句话,如果说的是论证的「下一步」而不是「同一步」,就切。

注意和「节」的区别:在节这一级,举例属于它要证明的论点,不切;
**在段这一级,一个完整的例子要单独成段**,例子前的主张、例子后的教训各是一段。

**长度:通常 5-12 行,中位约 8 行。**
- 少于 3 行的,并入相邻段,不要单独成段。
- 超过 16 行的,回去检查是不是漏了一个论证动作。
- 超过 20 行的,必须在这一段内部再找一刀。
- 本节不足 6 行时,允许整节就是 1 段。

**这是局部约束,不是全局配额。** 只在某一段确实过长时,才回到那一段内部再找一刀;
其余地方一律不动。不要为了凑段数在没有边界的地方硬切。
段数大约是「本节行数 ÷ 8」,只作超标预警。

特殊的节:
- 连续诵读经文的节:按经文里场景或事件的变化分段(人物介绍 / 家中的事 / 天上的场景……),不要一节经文一段。
- 祷告:按祈求的事项分段。

## 过渡句归属规则(必须遵守,否则每次结果都不一样)
承上启下的句子一律**归入它引出的那一段的开头**,不归入上一段的结尾。即:过渡句是新段的第一行。

**执行动作**:定完切点后,**逐段检查它的最后一行**。
如果这一行是在「为下文开口」,就把它移到下一段的开头,并同步修正两段的行号。
这一步只移动切点,不增加也不减少段数。

为下文开口的常见形状:
- 「因此呢,第十一节撒旦的控诉,你们就很好理解了。」—— 引出下一节经文
- 「因此呢,这个东西一旦是在这边,撒但就说什么？」—— 抛出下面要回答的问题
- 「然后我来敬畏你,而神本呢？」—— 前半句收尾,但**句末**在为下文开口,整行归后

## 非边界(一律不切)
a 连接词和填充词开头:「所以」「那」「因为」「但是」「其实」「你看」「好」。
  这些词**既不是切的理由,也不是不切的理由**。判断时把它们去掉,只看这一行在论证里走到了哪一步。
b 自问自答:问句之后 1-3 行内自己给出答案的,和答案同段。
  例:「这一切所有指那个指的是什么？」下一行「指的是第10节」。
c 复述与改口:「换言之」「我再说一遍」「我说哈」「因此我说……」在重复上文的主张,和上文同段。
d 例子内部:一个完整的例子从开始到讲完**不可分割**,
  哪怕内部出现「另外」「还有一拨人」「你信不信」也不许切开。
e 并列列举:「第一……第二……」如果支撑同一个论点,整体算一段。
f 一行带过的比方(如顺口带一句医院、学校要以人为本)不单独成段;
  只有展开成几行、自成一个完整画面的例子才单独成段。

## 写标题的顺序(必须遵守)
1. cuts 全部定完之后,才开始写第一个标题。
2. 写某一段之前,把这一段**从 start 到 end 逐行读完,一直读到最后一行**。
3. 先写 **ending**:这一段最后两三行落在什么内容上(10-30 字,用自己的话,不抄原句)。
   ending 是用来证明你读到了段尾的,不是标题必须写进去的内容。
4. 再写 **title**:读完整段之后,概括这一段整体在说什么。
   这一段的重点可能在开头的主张,也可能在中间的展开或结尾的结论,读完之后由你判断。
   **标题不必包含 ending 的内容,但必须是读完整段之后的概括,不能只根据开头几行来写。**
5. 自检:标题和段尾说的话有没有矛盾?
   如果结尾推翻、修正或限定了开头(先摆出别人的看法再反驳,先下结论再接一个「但是」),
   标题必须按读完结尾之后的意思来写,不能照开头写。

## 标题的要求
标题的用途是向量检索:它要能单独看懂,准确代表这一段完整说了什么。

**长度:20-110 字**(按字符计,含标点)。长度随段落内容而定,不要为凑字数重复或加空话:
- 3-6 行的段,约 20-50 字
- 7-12 行的段,约 40-80 字
- 13 行以上的段,约 60-110 字

**通顺流畅**:
- 写成一到两句完整的书面语,有主语、有谓语,读起来是一句通顺的话。
- 分句之间用逗号、「因此」「却」「即」「也就是」等连接,不要把名词一个个堆起来。
- 不要写成关键词清单(用顿号或分号串起一串名词)、电报体、半句话。
- 不保留口语词:哈、呃、啊、嘛、咱、你说你说。明显的同音错别字改成正确的词。
- 如果必须用分号拼接两个主语不同、回答的问题也不同的内容才写得下,说明这里该切成两段。

**不能脱离原文**:
- 只写这一段行号范围内说过的内容。不引申、不评价、不劝勉、不补充原文没说的结论或背景知识。
- 允许做的改动只有三种:
  (1) 把代词和简称补全成明确的对象(人名、书卷章节、术语),可以借助「所在节」的标题来确认指代;
  (2) 把口语改成书面语;
  (3) 改正明显的同音错别字。
- 标题里的每个专名和数字,要么出现在本段原文里,要么是为了补全本段的指代从节标题里取来的
  (本段说「第十一节」,标题可以写「约伯记1章11节」)。不许从本节的其他段搬事实。
- 保留身份:铺垫、设问、反例、别人的看法、待会儿要被推翻的前提,标题要写明它们的身份
  (「世人通常认为……」「撒但断言……」「以……为例」)。不许把它们写成讲者或圣经的主张。
- 保留限定词(「你认为的」「通常」「假设」)和极性(会/不会、够/不够、排除/未排除)。
- 不出现「讲员」「讲者」「作者」「本段」「这段」「本节」这类指代说话人或文本本身的词。
- 同一节里各段的标题不要雷同,每个标题都写出这一段特有的内容。

## 最高原则
- 切分:宁少勿多。漏切只是某段偏长;切错是把一个完整论证劈成两半。拿不准就不切,写进 uncertain。
- 标题:宁可朴素,不可失真。写不准的内容宁可不写,也不许编。

## 输出 json 格式
{
  "section": "5.4",
  "cuts": [158, 169, 173],
  "paragraphs": [
    { "start": 158, "end": 168, "ending": "……", "title": "……" },
    { "start": 169, "end": 172, "ending": "……", "title": "……" },
    { "start": 173, "end": 177, "ending": "……", "title": "……" }
  ],
  "uncertain": [
    { "line": 169, "reason": "……" }
  ]
}

字段说明:
- cuts:每一段的起始行,升序;第一个数必须等于本节 start。
- paragraphs:和 cuts 一一对应,start 等于对应的 cut,end 等于下一个 cut 减 1,最后一段的 end 等于本节 end。
- ending:这一段最后两三行落在什么内容上。下游不使用,只用来确保你读到了段尾;标题不必包含它。
- uncertain:拿不准的切点,写行号和原因。没有就给空数组。

## 三、user 消息模板

sec_no / sec_title 是这一节的编号和标题（来自切节结果）；lo / hi 是本节起止行号（原稿绝对行号）；
n 是行数；numbered 是本节逐行的「行号 | 内容」。

```
<FEWSHOT 全文>

━━━ 待处理的节 ━━━
所在节:{sec_no}「{sec_title}」
行号 {lo}..{hi},共 {n} 行。格式为「行号 | 内容」。

{numbered}

把这一节切成「段」。先写 cuts,第一个数必须是 {lo};最后一段的 end 必须是 {hi}。只输出 json。
```
