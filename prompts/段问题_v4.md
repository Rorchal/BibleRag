# 任务
为讲道转写稿的每一段写 2 个「用户会怎么问」的问题。问题会单独做成向量放进检索系统：用户的提问和问题越像，这一段越容易被搜到；问题写得泛，无关的搜索也会被吸到这一段。

# 输入
同一篇讲道、同一节里的若干段（JSON）：
- 讲道、主经文：这篇讲道的名称和主经文。
- paragraphs[]：每段的 id、title、text。
  - title：之前生成的段摘要，识别错字大多已改正。
  - text：语音转写原文，有识别错字、口头禅、结巴和重复。

# 提问的人
听过这篇讲道、熟悉和合本圣经的弟兄姊妹。几周后想找回其中一段，在搜索框打一句话，或向助手提问。

# 每段 2 个问题
1. 内容问：这段讲清楚的观点或结论。用提问人自己的话，通常是「为什么 / 是什么 / 该怎么看」。
2. 细节问：这段最有辨识度的一个具体抓手——比喻、例子、引用的经文、人名、讲员的亲身经历、一个特别的说法。写成凭模糊记忆找这段时会说的话。优先用 title 里没写到的细节。

# 规则
1. 答案在本段：答案必须能在本段 text 里找到。只做预告或过渡的段，只能问预告本身，不能问后面才展开的内容。
2. 只指向本段：同一批里的其他段不该同样好地回答它。
3. 换说法：不复述 title，不整句照搬 text——与 text 连续相同的字不超过 6 个。经文原句、书卷名、人名、俗语可以原样引用并加引号。
4. 写对字：text 的识别错字一律改正，拿不准看 title。常见错字：生命记→申命记，腓利比→腓立比，拖住万有→托住万有，撒旦→撒但，气掉→弃掉，旧恩→救恩，轨迹→诡计（魔鬼的诡计），征战→争战（属灵争战），四八人→示巴人，东方自大→东方至大，一年四次→一连四次。口头禅、结巴、重复不带进问题。
5. 补全经文：讲员说「第十节」「9到12节」，按主经文补成「约伯记1章10节」这样。
6. 不用指代：不写「这段」「本段」「上文」「这一节」，提问人看不到上下文。可以写「牧师」「讲道里」。
7. 格式：每个问题 8～35 字，一句话，以问号结尾；两个问题不问同一件事。
8. kind 四选一：讲道 / 经文诵读（整段在朗读圣经原文）/ 祷告 / 开场过渡（问候、流程安排、预告）。非「讲道」的段也照样写 2 个问题。

# 好坏对照
text 片段：「……比如说假牛肉吧，你不能认为全部用鸭肉代替才是假牛肉吧。人家能不能一半牛肉一半鸭肉去拼接呢？可以。那你不能说那是真牛肉吧？」
- 坏（太泛，别的段也能答）：牧师怎么看真假掺杂的问题？
- 坏（照搬原文）：为什么不能认为全部用鸭肉代替才是假牛肉？
- 坏（用了指代）：这段的牛肉比喻想说明什么？
- 好（内容问）：一半真一半假的东西，为什么还是不能算真的？
- 好（细节问）：牧师拿牛肉掺鸭肉打的比方是什么意思？

# 输出前自查
每个问题过一遍：答案在本段 text 里吗？换成同一批别的段还答得上吗？有错字、指代词、整句照搬吗？不合格就改。

# 输出
只输出一个 JSON 对象，不要任何其他文字，不要重复 title 和 text：
{"paragraphs":[{"id":"原样照抄输入的 id","kind":"讲道","questions":["……？","……？"]}]}
按输入顺序，每个输入段一条。
